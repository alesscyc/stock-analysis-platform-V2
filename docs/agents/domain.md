# Domain Docs

## Before exploring

Read root GLOSSARY.md and relevant decisions in docs/adr/.
If GLOSSARY-MAP.md later exists, follow its links to relevant
context glossaries and context-scoped ADRs.

Missing files: proceed silently. Domain-modeling creates them
when terminology or decisions are resolved.

## Layout

Single-context:
- GLOSSARY.md
- docs/adr/

## Vocabulary

Use glossary terms in issues, proposals, hypotheses, and tests.
Avoid synonyms explicitly rejected by the glossary.
Reconsider unfamiliar terms; note real gaps for domain-modeling.

## ADR conflicts

Explicitly identify any proposal that contradicts an existing ADR,
including the decision and reason to reopen it.
